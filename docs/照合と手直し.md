# 照合と手直し

工程8の照合（`pipeline/08_verify.mjs`）の作り、［要確認］の印の付け方、人が会議録の原文で確かめて直した結果。全体の作り方は [作り方.md](作り方.md)、コマンドは [動かし方.md](動かし方.md) の「工程8 照合」と「手直し」。

## 照合するもの

AI は使わない。文字が一致するかを見るだけなので、何度流しても同じ結果になる。

1. 工程5の記録 ↔ 会議録の原文: 記録の数字と「」の引用（約束）が、記録の付けた発言の原文にそのままあるか
   - 数字の全角・半角、カンマ、「．」「％」はそろえて比べる（原文は全角数字、記録は半角数字のことが多い。そろえる前は約9%が「原文にない」と出た）
   - 記録の付けた発言になくても、同じまとまり（1人分の質問と答弁）の別の発言にあれば「別の発言」として分ける（発言番号の付け間違いで、中身は原文どおり）
2. 工程6・7のまとめ ↔ 引いた記録: まとめの文の数字と「」が、その文が出典に挙げた記録（見出し・要旨・数字・約束・日付）にあるか。出典のない文がないか
   - 記録になくても、引用と2桁以上の数字は、引いた記録のまとまりの会議録の原文にあれば確かめられたものとする（記録の引用は工程5で Haiku が写したもので、原文と少し違うことがある）。1桁の数字は原文のどこかに出やすいので、原文では見ない
   - 拾わないもの（事実の数字ではない）: 任期の区切りの年（「2019年以降は」「2007〜2011年は」で、引いた記録にその時期のものがあるとき）、「2019年以降のまとめには出てこない」の年、「2〜3月」の2のような月の幅、「会議録は2026年6月ごろの分まで」の注記、月・日、「3年」のような短い期間
   - 20年のまとめの「市の答弁の変化」で、項目の1文目が出典のない書き出しの文でも、続く文がすべて出典付きで、続く文にない数字や「」がなければ要確認にしない（続く文のまとめ。README の頭にそう書いてある）

照合には会議録の原文（`data/struct/`、Git の外）が要る。原文のない年があると `08_verify.mjs` は止まる。結果は `verify/`（Git に入れる）と、人が見る一覧の `topics/要確認.md` に書く。

## 消さずに印を付ける

照合で合わなかった文は、消さず、AI に直させもせず、印を付けて人が原文で確かめることにした。

- 照合には拾いすぎがあり、消すと正しい文まで消える
- 直すかどうかは、原文を見て人が決めること。AI に直させると、新しい誤りが入りうる
- 印があれば、人前で使う前に気づける

印は `.md` の文の後ろに「［要確認: 引用が原文と一致しない］」のように付く（`07_history.mjs --render`、`06_bundle.mjs --render` が `verify/summaries.jsonl` を読んで付ける）。印の種類は、引用が原文と一致しない、数字が原文と一致しない、出典の番号が誤り、引用の出典が見つからない、数字の出典が見つからない、出典なし。

会議録へのリンクは記録からコードで付けるので、形が合っていれば全部合う。年代の違う3件（2008・2016・2025年）を開き、ページの題名が記録の会議と一致することを確かめた。全部のリンクは開いていない。

## 人の手直し

AI が作ったまとめ（`topics/<話題>/history.json`）は直接書き換えない。工程7を流し直すと消えるため。代わりに `pipeline/fixes/07_history.jsonl` に1行ずつ「直す前の文字列（`before`）→ 直した後（`after`）」と理由（どの記録の原文と照らしたか）を書き、`node pipeline/07b_fix.mjs` で当てる。

- 当て済みのもの（`after` がすでにあるもの）は飛ばすので、何度流してもよい。工程7を流し直したら、もう一度流す
- `before` が見つからない・2か所以上にあるときは止まる。流し直しで文が変わったら、手直しの行を書き直す
- 当てた手直しは `history.json` の `fixes` に残り、README の頭に件数が出る
- 当てたら `08_verify.mjs` → `07_history.mjs --render` → `06_bundle.mjs --render` の順に流す
