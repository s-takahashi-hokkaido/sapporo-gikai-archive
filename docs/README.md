# エンジニア向けの資料

札幌市議会の会議録（2007〜2026年の本会議と委員会）を、話題ごと・区ごとに辿れる形にした仕組みの説明。読む人向けの入口は [README.md](../README.md)。

## 全体の流れ

```
会議録検索システム
  │ 工程1 原本の取得（約3,500日分の会議）
  │ 工程2 Markdown への変換
  │ 工程3 構造化（発言、目次、会派の名簿）
  ▼
まとまり 21,055件（1人分の質問と、それへの全答弁）
  │ 工程4 話題の一覧（53話題）を先に固定
  │ 工程5 分類・要約（AI。まとまり1件ずつ）
  ▼
記録 54,813件（records/。話題、地域、地名、問・答の要旨、数字、約束の引用、出典）
  │ 工程6 話題×任期のまとめ（AI。265組）
  ▼
話題×任期のまとめ（bundles/）
  │ 工程7 20年のまとめ（AI。53話題）
  ▼
話題ごとの20年のまとめ（topics/）
  │ 工程8 照合（数字と引用を、引いた記録と会議録の原文で確かめ、［要確認］の印を付ける）
  ▼
区の入口（areas/。記録を区ごと・話題ごと・地名ごとに並べる）
```

AI が読むのは、工程5の「まとまり1件」、工程6の「話題×任期の記録」、工程7の「話題の5任期分のまとめ」だけ。取得、変換、分割、並べ替え、照合はコードでやる。

## 工程、スクリプト、出力、モデル

| 工程 | スクリプト | 出力 | モデル |
|---|---|---|---|
| 1 原本の取得 | `pipeline/01_download.mjs` | `data/raw/`（Git の外） | なし |
| 2 Markdown への変換 | `pipeline/02_to_markdown.mjs` | `data/md/`（Git の外） | なし |
| 3 構造化 | `pipeline/03a`〜`03f` | `data/struct/`（Git の外） | なし |
| 4 話題の一覧 | `pipeline/04a`〜`04c`、人が `pipeline/topics.csv` を直す | `pipeline/topics.csv` | 試行だけ Opus 5.5 |
| 5 分類・要約 | `pipeline/05_run_all.mjs`、`05_classify.mjs` | `records/<年>.jsonl` | Haiku 5.5（落ち続けた4件は Sonnet 5.5） |
| 6 話題×任期のまとめ | `pipeline/06_bundle.mjs` | `bundles/<話題>/<任期>.json`、`.md` | 細かく分けた5分野は Opus 5.5、ほかは Sonnet 5.5（2回落ちたものは Opus） |
| 7 20年のまとめ | `pipeline/07_history.mjs`、手直し `07b_fix.mjs` | `topics/<話題>/history.json`、`README.md`、`topics/README.md` | Opus 5.5 |
| 8 照合 | `pipeline/08_verify.mjs` | `topics/要確認.md`、`verify/` | なし |
| 年表（全市） | `pipeline/07a_timeline.mjs` | `topics/<話題>/年表.md`（Git の外） | なし |
| 区の入口 | `pipeline/09_area.mjs` | `areas/README.md`、`areas/<区>/` | なし |

工程5〜7は API（Message Batches）で流した。effort はどれも medium。

## かかった時間

| 工程 | 時間 |
|---|---|
| 1 原本の取得 | 約2時間（1.5秒に1件、約3,500件） |
| 2 Markdown への変換 | 数秒 |
| 3 構造化 | 15秒ほど |
| 4 話題の一覧の試行 | 300件をバッチで6分 |
| 5 分類・要約 | 約5時間（送り直しのバッチの処理待ちを含む） |
| 6 話題×任期のまとめ | 試行 約20分、本番 約1時間10分 |
| 7 20年のまとめ | 約15分 |
| 8 照合 | 1分ほど |
| 年表（全市） | 数秒 |
| 区の入口（10区） | 数秒 |
